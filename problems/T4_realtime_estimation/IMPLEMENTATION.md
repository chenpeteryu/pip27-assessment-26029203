# T4 第一版实现与验证记录

日期：2026-10-23。依据官方 v0.2.0 手册和模板，来源为算法/problems/T4_realtime_estimation/ 顶层 src。算法内容保持源文件原样，仅规范化 LF 换行。测试、实验、交接与构建材料留在算法工作区，不随本次作答导入；下述结果从原实现记录和本次复测整理。

## 实际算法

本版使用**滑动窗口高斯过程回归**，没有把对话中的 α-β、局部多项式或卡尔曼建议写成已实现功能。
官方 README 描述了由不同宽度高斯事件叠加的轨迹，因此使用平滑核直接描述局部相关性，避免三次多项式长期外推失控。

给定已接收的历史 `t_i,y_i`，核为：

`k(t,s) = A² [exp(-(t-s)²/(2 ell²)) + 10]`。

常量核允许未知局部偏置。以窗口观测均值 `m` 为数值中心，通过 Cholesky 分解求解
`alpha = (K + sigma_est² I + jitter I)^(-1)(y-m)`，输出 `m + k_*^T alpha`，不显式求逆。

- 不等间隔三点线性插值残差估计噪声方差，除以对应系数平方和；最多使用最近 256 帧。
- 由历史观测方差扣除噪声估计信号核幅度，幅度平方保留下限 1。
- Basic 使用最近 1.5 s，拓展使用最近 3 s；最多均匀选择 192 个历史点，包含最新点。历史缓存最多 512 帧。
- 每 10 次观测更新，使用当前历史的边际似然在 5 个平滑尺度间选择；首段使用固定初始尺度，不读取样例配置中的真实噪声。
- Basic 候选尺度为 `0.26×{1,1.3,1.7,2.2,2.9}` s；Extra1/2 为 `0.50×{...}` s；Extra3 为 `0.60×{...}` s。
- 首帧直接输出观测值，启动阶段参与所有误差统计。
- 所有时间差由整数纳秒相减后转为相对秒，不以绝对大时间戳构建设计矩阵。
- 单次拟合复杂度 `O(N³)`，内存 `O(N²)`，预测长度 J 的复杂度 `O(NJ)`；N≤192、J≤101。选尺度时额外做 5 次拟合。

这是基于平滑先验的预测，并不保证任意平滑轨迹或未知正式点都通过。

## 节点与调度

- `src/estimator_node.cpp`：唯一 ROS 2 入口，节点 `/signal_estimator`，参数 `assessment_mode` 为整数 0–3，仅允许首帧前修改。
- QoS：Reliable、Volatile、KeepLast(256)。消息保持官方 `std_msgs/Header header; float64[] values` 协议。
- Basic 每帧输出 `/signal/estimate`，完整复制输入 Header，返回一个当前估计值。
- 拓展输出 `/signal/prediction`，每条含 21/41/101 个点。
- 读取首帧 DDS `source_timestamp`，通过系统时钟与单调时钟配对映射实际发布时间；不使用首个回调到达时刻作为真实零点。无法获取 DDS 发布时间时拓展报错退出。
- 1 ms 定时回调检查绝对发送期限；未到 `T0+k×5 ms` 不发送，晚到时按序补发，每次最多 8 条。补发不能消除真实迟到，仍可能被判失败。
- 虚拟起点严格使用首帧 Header 纳秒加 `k×5,000,000`；即使观测抖动，也不改用最新观测时间作为起点。
- `src/prediction_stream.hpp` 保存收到但尚未到虚拟使用时间的观测。生成某起点时只消耗 `observation_stamp <= prediction_start` 的项，防止回调积压时使用未来数据。
- 默认单线程执行器串行处理参数、订阅和定时器，避免状态竞态。没有逐帧日志、忙等待或额外线程。
- 未提供末帧通知，按官方 README 允许的行为在末帧后继续正常输出，直到 SIGINT。
